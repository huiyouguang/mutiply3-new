# CodeBuddy Agent 使用指南

> AI Knowledge OS 已从 Claudian 迁移至 CodeBuddy Agent。本指南覆盖所有可用命令和 Obsidian 联动方式。

---

## 一、系统架构速览

```
你在 Obsidian 中捕获/浏览/查看
           ↓
你在 CodeBuddy 中说命令 → Agent 读写 Vault 文件
           ↓
结果写回 Obsidian，实时可看
```

**三个角色的分工**：

| 你在哪里 | 做什么 |
|----------|--------|
| Obsidian | 捕获（Inbox/Thino/Clippings）、浏览、查看结果 |
| CodeBuddy | 分析、分类、生成、分发、打标签 |
| 两者结合 | 你判断 + AI 加工 + 知识沉淀 |

---

## 二、所有命令速查表

### 🏭 Inbox 处理

| 命令 | 功能 | 示例 |
|------|------|------|
| `处理 Inbox` | 批量分析 Inbox 内容，按领域路由分发到主知识库 | `把 Inbox 里的内容都处理掉` |
| `整理收件箱` | 同上 | `帮我清理下收件箱` |
| `处理 Inbox，但只处理 XX 领域的` | 按领域筛选处理 | `处理 Inbox 里关于注会的文件` |

**工作流**：Inbox 文件 → Agent 分析内容 → 确定 domain/type/rating/tags → 按路由表分发到外层目录（如 `04成长/知识管理/004 注会/`）→ 清理原始文件

---

### 📝 知识笔记操作

| 命令 | 功能 | 示例 |
|------|------|------|
| `创建知识笔记` | 按模板生成新知识笔记并路由分发 | `帮我创建一篇关于长期股权投资的笔记` |
| `记录这个概念：XXX` | 同上，指定主题 | `记录这个概念：合并报表抵消分录` |
| `把这篇笔记补充完整` | 补充缺失的 frontmatter 字段和正文 | `把 04成长/知识管理/004 注会/合并报表.md 补充完整` |
| `给这篇笔记推荐链接` | 分析内容，推荐 3-5 个 Wikilink | `给合并报表笔记推荐关联链接` |
| `这篇笔记应该升级为 evergreen` | 评估笔记状态并更新 | `检查这篇笔记是否达到 evergreen 标准` |

- 考试类 → `04成长/知识管理/{考试名}/`

## 三、Obsidian 中的操作方式

### 3.1 捕获入口

你可以在 Obsidian 中通过这些方式把信息送入系统：

| 方式 | 路径 | 说明 |
|------|------|------|
| **AI Knowledge OS Inbox** | 左侧 Ribbon 紫色大脑图标 → Inbox | 手动创建笔记放入加工站 |
| **Thino 快记** | `thino/` 文件夹 | 快速记录灵感，稍后通过 Agent 处理 |
| **Clippings** | `Clippings/` 文件夹 | 网页剪藏内容 |
| **直接拖入** | `00 Inbox/` 或 `AI Knowledge OS/00-Inbox/` | 任何 .md 文件拖入即可 |

### 3.2 查看结果

加工后的知识笔记会出现在：

| 去哪儿看 | 路径 |
|----------|------|
| **知识中心（全库）** | Obsidian 中打开 `AI Knowledge OS/Knowledge/Knowledge.base` |
| **仪表盘** | 打开 `01 主页/仪表盘.md` |
| **项目视图** | 打开 `AI Knowledge OS/Projects/Projects.base` |
| **知识地图** | 打开 `AI Knowledge OS/Knowledge Map.canvas` |
| **文件管理器** | 直接在 Obsidian 文件树上浏览各目录 |

### 3.3 典型工作流

**场景 1：处理一篇微信公众号文章**

```
1. 在 Obsidian 中打开 AI Knowledge OS Inbox，粘贴文章
2. 切换到 CodeBuddy，说"处理 Inbox"
3. Agent 分析后，知识笔记自动出现在 04成长/ 或 03Life os/ 对应目录
4. 回到 Obsidian 查看结果
```

**场景 2：备考注会，记录一个重要概念**

```
1. 在 CodeBuddy 中直接说"创建知识笔记：合并报表的商誉计算"
2. 如果内容不完整，说"把这篇笔记补充完整"
3. Agent 补充正文、推荐 Wikilink、写入注会目录
```

**场景 3：每周日做知识复盘**

```
1. 在 CodeBuddy 中说"生成周报"
2. Agent 输出本周新增笔记、推荐连接、知识缺口
3. 根据周报建议，说"找孤立笔记"并逐个处理
4. 说"检查项目进度"，更新项目状态
```

**场景 4：准备写一篇关于 AI Agent 的公众号文章**

```
1. 在 CodeBuddy 中说"用内容助手写一篇关于 AI Agent 落地的文章"
2. Agent 搜索 Vault 中所有关于 AI Agent、FDE、企业 AI 转型的笔记
3. 生成引用清单 + 完整稿件框架
4. 稿件保存到工作/ 目录
```

## 五、笔记质量标准

Agent 创建的知识笔记会按以下标准评级：

| 状态 | 含义 | 特征 |
|------|------|------|
| 🌱 seed | 种子 | 初建、信息不完整、链接 ≤2 |
| 🌿 growing | 生长中 | 内容较完整、链接 3-5 个 |
| 🌳 evergreen | 常青 | 充分论证、多篇引用、稳定可复用 |

| 价值分 | 含义 |
|--------|------|
| 1 | 仅记录链接/标题，无分析 |
| 2 | 有摘要无独立判断 |
| 3 | 有完整定义+来源，可快速查阅 |
| 4 | 有证据链+适用边界，可直接引用 |
| 5 | 核心概念，被多处引用，反复验证 |

## 六、常见问题

### Agent 会把文件放到错误的位置吗？
Agent 根据 frontmatter 的 `domain` 字段查路由表分发。如果你发现放错位置，直接说"把 XX 笔记移动到 YY 目录"即可。

### 批量操作会不会误删文件？
批量操作先汇报数量，等你确认后才执行。Inbox 处理时原始文件会归档到 `.archive/` 而非直接删除。

### 能不能同时用 Obsidian 和 CodeBuddy？
可以。它们是独立工具，读写的是同一份 Vault 文件。你在 Obsidian 打开文件，在 CodeBuddy 说命令——两边互不冲突。

### 之前 Claudian 的功能还能用吗？
原 Claudian 提供的能力现在由 CodeBuddy Agent 完全覆盖，且更强大（支持批量处理、路由分发、全库分析）。

### 如果 CodeBuddy 不在这个工作区怎么办？
打开 CodeBuddy 时选择 `mutiply3` 目录作为工作区，Skill 会自动加载。

## 七、高级技巧

1. **链式操作**："处理 Inbox → 然后生成周报"（一次完成两步）
2. **精确路径**：你可以直接指定文件路径让 Agent 操作特定笔记
3. **上下文记忆**：Agent 会记住当前对话中的上下文，连续操作无需重复描述
4. **人设版本**：Agent 输出风格偏实干，直接给结果，不啰嗦
